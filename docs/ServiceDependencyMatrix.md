## Reading This Table

- **"Hard" startup dependency** = the service should not report itself ready (and, per [Deployment.md](Deployment.md), Railway shouldn't route traffic to it) until that dependency is reachable.
- **"Soft" dependency** = the service starts and serves most or all of its traffic without it, degrading a specific feature rather than failing outright — this is a deliberate design choice (§ [ADR 0007](adr/0007-redis-dependent-features-fail-open.md) for Redis; the outbox pattern's whole purpose for RabbitMQ) and should not be "fixed" into a hard dependency without revisiting why it was made soft.
- **Zero services reference another service's database or project directly** — every cross-service interaction in this table is either a REST call (routed through the network, never a compile-time reference) or a RabbitMQ event. See [ProjectReferenceDiagram.md](ProjectReferenceDiagram.md) for the compile-time reference rules this matrix implies.
